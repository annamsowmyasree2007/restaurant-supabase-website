# Hungry Hunt

A responsive, framework-free restaurant website for Hungry Hunt in Tirupati, Andhra Pradesh. The brand celebrates authentic Andhra and South Indian flavours in a peaceful, modern dining setting. The menu is fetched at runtime from Supabase; menu entries are not embedded in the HTML.

## Features

- Six standalone pages: Home, About, Menu, Gallery, Reservation, and Contact
- Accessible mobile navigation, keyboard focus states, skip link, and labeled form fields
- Live menu loading from Supabase with category filtering, loading/empty/error states, and invalid-row handling
- Frontend reservation form with browser validation (does not submit or store booking requests)
- Lazy-loaded food and restaurant photography and an embedded Google Map
- Static deployment configuration for Vercel

## Supabase setup

1. Create a Supabase project.
2. In **SQL Editor**, run the schema and policy below.
3. Replace the sample image URLs in the insert statement if desired, then run the insert.
4. In **Project Settings → API**, copy the Project URL and browser-safe publishable key. Older projects may label the browser-safe key `anon`.
5. Put those two values in `js/supabase.js`. Never put a secret/service-role key or database password in frontend code.

### Database schema and read policy

```sql
create table if not exists public.menu_items (
  id bigint generated by default as identity primary key,
  name text not null,
  category text not null,
  description text,
  price numeric not null,
  image_url text,
  is_available boolean default true
);

alter table public.menu_items enable row level security;

grant select on public.menu_items to anon;

create policy "Public can read menu"
on public.menu_items
for select
to anon
using (true);
```

If the policy already exists, do not create it a second time. The `anon` role is granted read-only access to menu rows; there is no public insert, update, or delete policy.

### Client configuration

Edit these placeholders in `js/supabase.js`:

```js
const SUPABASE_URL = "YOUR_SUPABASE_PROJECT_URL";
const SUPABASE_KEY = "YOUR_SUPABASE_PUBLISHABLE_KEY";
```

The website uses the Supabase browser client to select available rows from `menu_items`. The publishable/anon key is intended for browser use when Row Level Security is configured correctly. It is not a database password. Never use the service-role/secret key in this project.

## Run locally

Open `index.html` in a browser, or use the VS Code **Live Server** extension. Supabase requires internet access and valid project settings. Until configured, the menu displays a setup message instead of a blank section.

## Test the menu

1. Configure Supabase and load the website.
2. Confirm the sample items appear.
3. Add another row in Supabase and refresh; it should appear without editing the HTML.
4. Set an item's `is_available` value to `false` and refresh; it should be hidden.
5. Try the category filters and check the browser console for errors.

## GitHub and Vercel deployment

1. Create a GitHub repository named `restaurant-supabase-website`.
2. From a terminal opened in this folder, initialize and push the project:

   ```powershell
   git init
   git add .
  git commit -m "Build Hungry Hunt restaurant website"
   git branch -M main
   git remote add origin https://github.com/YOUR_GITHUB_USERNAME/restaurant-supabase-website.git
   git push -u origin main
   ```

3. In Vercel, import that GitHub repository. It is a static HTML project; leave the framework preset as **Other** and do not set a build command or output directory.
4. Deploy, open the generated URL, and test navigation, mobile layout, menu loading/filtering, map, and reservation validation.
5. If you update the Supabase project values, commit and push the change so Vercel deploys the update. Only the publishable/anon key belongs in browser code.

## Reservation form

The included form validates name, phone, date, time, and a guest count from 1 to 12. It does not transmit or persist a reservation, and its confirmation message makes that clear. To accept reservations online, implement a backend or a Supabase insert policy with appropriate abuse protections; never expose a secret key.
